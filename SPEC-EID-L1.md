# SPEC-EID-L1 — Промежуточный диалект EID, уровень L1

**Версия:** v0.9 (Q11 уточнён: точки разрыва + обязанность связывания; НЕ заморожен)
**Статус:** freeze только после зелёного этапа 6. До этого — ревизии через `CHANGELOG.md`.
**Связанные документы:** `COVERAGE.md` (диспозиции кодов, финальная таксономия), `EQUIVALENCE.md` (L2-контракт), `CORPUS-CONTRACT.md` (что чем проверяется), `grammar.ebnf` (выводится из этого документа, не наоборот).

---

## 0. Место в системе

EID/L1 — промежуточное представление (IR) для трансляции G-кода между диалектами.
Канонизация: `диалект → EID/L1`. Эмиссия: `EID/L1 → диалект`.
Любой-в-любой доказывается через совпадение EID AST (см. `EQUIVALENCE.md`).

**Скоуп v0.0: 3-линейные оси, фрезерная кинематика.** Токарный режим (G96/G97 CSS,
G7/G8 диаметральный размер), 4+ оси, RTCP — вне скоупа, до этапов 10/12.

---

## 1. Скоуп и не-цели

### 1.1 L1 — статический язык движения

L1 покрывает **только статическое подмножество**: программа, вся геометрия которой
вычислима без исполнения. Запрещено и отклоняется — класс отказа различается
по причине (v0.2, ревью B1):

- `E_RUNTIME_STATE` — значение зависит от момента исполнения: `#`-параметры
  и выражения с ними, чтение состояния станка (`#<_x>` в LinuxCNC, системные
  переменные), block delete;
- `E_UNSUPPORTED_SYNTAX` — конструкция вне грамматики L1: `if / while / do /
  repeat`, O-code / макро-подпрограммы и их вызовы (`G65`, `M98`/`M99` —
  см. Q10), вендорские макросы;
- `E_UNSUPPORTED_SEMANTICS` — синтаксис распознаваем, семантика не
  представима ходами (per-code — матрица `COVERAGE.md`).

Обоснование: 99% реального контента — вывод CAM-постов, он статический.
Параметрика — уровень L2, этап 12, отдельное решение.

### 1.2 Не-цели v0.0

| Не-цель | Причина | Куда отложено |
|---|---|---|
| Параметрические программы | вне статического подмножества | этап 12 (L2) |
| Токарные режимы (CSS, диаметр) | отдельная кинематика/семантика | этап 10+ |
| 4/5 осей, RTCP | скоуп MVP — 3 линейные оси | этап 12 |
| Пробинг (G38.x), in-cycle measurement | сенсорная семантика | этап 12 |
| Компенсации (G41/G42, G43) | см. §8 | решение отдельно |
| Сохранение process intent (сворачивание развёрнутых циклов) | запрещено, §7 | никогда |

## 2. Принципы дизайна

1. **Resolved-state ops.** Каждая операция несёт полное разрешённое состояние
   (§4) своими полями. Состояние — не поток событий, а поля операции.
   Следствие: правила переупорядочивания не нужны (см. `EQUIVALENCE.md`).
2. **Позиционная независимость.** Каждый motion-оп несёт `start` и `end`
   **явно**. Никакой оп не требует предыдущего для интерпретации.
   Инкрементальные режимы разрешаются в абсолютные при канонизации.
   **`start: vec3 | unknown`** (v0.8, Q11 — пилот-находка №1; уточнено
   v0.9). unknown возникает **ровно в точках разрыва фрейма**:
   (a) первый motion-оп программы без якоря (нет `frame_preset` /
   `wcs_set_here`; не-motion опы перед ним роли не играют);
   (b) первый motion-оп после смены `wcs` на систему без in-text
   `wcs_define` (reading прыгает на неизвестную разность origin'ов —
   `Δ` константен, `O_wcs` внешний, EQUIVALENCE §1.3);
   (c) первый machine-frame ход — start в машинных координатах не
   вычислим (`M₀` внешний); **последующие** machine-frame ходы цепляются:
   start = end предыдущего;
   (d) первый WCS-ход после machine-frame ходов (reading = M_target −
   O_wcs − Δ содержит `M₀` — не вычислим из текста никогда).
   **Обязанность связывания (v0.9):** во всех остальных случаях
   `start = end предыдущего motion-opa` — канонизатор **обязан вычислить**;
   unknown вне точек разрыва — баг канонизации, не легальное состояние
   (EQUIVALENCE §3: unknown vs known — расхождение, R3 красный).
   Оп с `start=unknown` обязан быть RAPID или LINEAR (путь — прямой
   физический отрезок, конец известен); ARC с `start=unknown` —
   `E_RUNTIME_STATE` (геометрия дуги требует числового старта). Такой оп
   обязан задать **все три** координаты `end` — частичный end наследует
   неизвестное: `E_RUNTIME_STATE`.
3. **Явная модальность.** Ни одна модальная группа диалекта не переносится
   в EID неявно; всё, что модально в диалекте, разрешено в поля опов
   или отклонено.
4. **Одна каноническая форма** для каждой сущности (дуги — §6; циклы — §7).
   Обратное свёртывание паттернов (распознавание «это похоже на G83»)
   **запрещено** — оно делает канонизацию неидемпотентной.
5. **Одна система единиц на программу.** Переключение единиц в середине
   программы — отказ.
6. **RAW same-dialect only.** RAW-блок (§9) не транслируется кросс-диалектно.
7. **Никакого runtime.** Любая конструкция, чьё значение зависит от состояния
   станка в момент исполнения, — вне L1 (§1.1, §8).

## 3. Модель программы

```
Program := {
  eid_version : "EID/L1 v0.0"        // magic header каждого EID-файла
  units       : mm | in              // глобально, одна на программу (§2.5)
  path_mode   : exact_path | exact_stop | blend(t)   // метаданные (G61 / G61.1 / G64 P-Q); Q3
  frame_preset: none | g92(vec3, wcs)  // присваиваемые значения + WCS, активная в момент пресетки; ограничение ниже
  ops         : [Op]                 // плоский упорядоченный список
}
```

**Семантика `frame_preset` (G92, v0.1):** значения — это **координаты,
присваиваемые текущей позиции** («текущее положение становится X0 Y0 Z0»),
а не вектор сдвига. G92 позиционно-зависим → разрешён **только как пресетка
программы** (до первого motion-опа): относительная геометрия и координаты в
WCS-фрейме последующих опов определены, **машинные** координаты — нет
(см. правило machine-frame, §5.3). G92 в середине программы,
G92.1/92.2/92.3 — `E_UNSUPPORTED_SEMANTICS` (Q4/Q5).
**Композиция с `state.wcs`:** `frame_preset` — **глобальный offset поверх
любой WCS**, не привязан к одной системе; координаты motion-опов живут
в composed-фрейме `wcs ⊕ frame_preset`. Поле `wcs` в узле пресетки
фиксирует систему, активную в момент G92: `Δ` зависит от её origin
(EQUIVALENCE §1.3), поэтому эмиссия обязана выбрать её **до** G92-блока.
Точная формула и контракт самодостаточности — `EQUIVALENCE.md` §1.

**Инвариант валидности программы** (проверяется парсером EID):
- `program_end` присутствует **ровно один раз**, является последним опом;
  опов после него нет; в минимальной программе — единственный оп (v0.6:
  прежнее «первым опом быть не может» противоречило минимальной программе);
- программа без motion-опов (заголовок + `program_end`) валидна;
- motion-опы с `frame = wcs` имеют непустой `wcs`;
- `start` motion-опов: unknown только в точках разрыва фрейма (§2,
  принцип 2); вне их — `start = end предыдущего motion-опа`, вычисление
  обязательно (v0.9);
- `linear`/`arc` **в итоговом AST** (после отбрасывания zero-length, ниже)
  требуют `feed != none` — **текущего модального** значения (§4);
  отсутствие любого `F` до первого содержательного linear/arc —
  `E_INVALID_INPUT`;
- motion-оп без движения (`start == end`; для дуги — при `sweep ≠ 360°` и
  `pitch = 0`) **отбрасывается канонизатором с notice** — не ошибка:
  контроллеры исполняют его как легальный no-op, CAM-посты такой эмитят
  (v0.6; согласовано с нулевой дугой §6);
- поля `state` связны между соседними опами (валидация разрешённого
  состояния — на этапе канонизации исходника, не EID);
- `path_mode` глобален: переключение G61/G64 в середине программы —
  `E_UNSUPPORTED_SEMANTICS` (v0.1; пересмотр по корпусу — Q3).

## 4. Модель состояния (resolved-state)

Каждый оп несёт снапшот `state`. Поля:

| Поле | Тип | Разрешение из диалекта |
|---|---|---|
| `feed` | `float \| none` | **Модальное значение** (resolved-state, §2): текущий активный F программы. `none` — только если F ещё ни разу не задан. **G0 не сбрасывает feed** (в G-коде F модален и переживает G0; иначе после `G0; G1` без F станок использует предыдущий F — «none на rapid» ломал resolved-state, v0.1). Разрешение: G94 — F как есть; G93 (inverse time) — `feed = len(траектория) × F` (движение занимает `1/F` мин; длина дуги — §6). linear/arc при `feed = none` — `E_INVALID_INPUT`. |
| `spindle` | `off \| cw(rpm) \| ccw(rpm)` | M3/M4/M5 + S; G96 CSS вне скоупа (§1.2) |
| `coolant` | `flood: bool, mist: bool` | M7/M8/M9 |
| `tool` | `int \| none` | T..M6 — **физически установленный** инструмент; отсутствие = не менялся. Предвыбор (T без M6 в LinuxCNC) и M61 (номер без физической смены) — вне L1: RAW; кандидат ревизии — отдельное поле `selected_tool` (COVERAGE §7) |
| `wcs` | `G54..G59.3` | выбор системы координат |
| `frame` | `wcs \| machine` | G53 — разовый ход в машинных координатах |

**Плоскость (G17/G18/G19) — НЕ поле состояния.** Дуги разрешаются в 3D (§6),
циклы разворачиваются в явные ходы (§7). Плоскость — модальное состояние
**парсера диалекта**: нужна для интерпретации IJK (в LinuxCNC пары осей
зависят от плоскости, в GRBL I/J/K всегда X/Y/Z-смещения — различие
поглощается адаптером). Канонизатор валидирует: перпендикулярная компонента
`(center − start)` ≈ 0; расхождение — `E_INVALID_INPUT`.

## 5. Инвентарь опов

10 типов. Три группы: движение (3), процесс (4), фрейм (2), сырое (1).

### 5.1 Движение — все с `state`, все с явными `start` и `end`

| Оп | Поля | Источник |
|---|---|---|
| `rapid` | `start, end, state(frame)` | G0 |
| `linear` | `start, end, state(feed, frame)` | G1 |
| `arc` | `start, end, center, direction, sweep, pitch, state(feed, frame)` | G2/G3 — форма в §6 |

**`start`: `vec3 | unknown`** (v0.8, §2 принцип 2 / Q11); `end` — всегда `vec3`.

### 5.2 Процесс

| Оп | Поля | Источник / примечания |
|---|---|---|
| `dwell` | `seconds: float, state` | G4. Единицы — секунды, **подтверждено документацией обоих диалектов** (grbl interface.md: «P is in seconds, must be > 0.0»; LinuxCNC gcode.html: P float seconds). Fanuc X/P различаются — адаптер этапа 10. `seconds == 0` → drop+notice (аналогия zero-length §3 — no-op); `seconds < 0` → `E_INVALID_INPUT`. Dwell — процессно-значим (стружка, температура), поэтому op, не аннотация. |
| `tool_change` | `tool: int, state` | T..M6. grbl 1.1: `E_UNSUPPORTED_SEMANTICS` при эмиссии; grblHAL: поддержан. |
| `program_stop` | `optional: bool, state` | M0 (`optional=false`), M1 (`optional=true`; поведение M1 зависит от настройки станка — см. `EQUIVALENCE.md`). |
| `program_end` | — (финальный state не хранится) | M2/M30 → один оп. Различие M2/M30 (сброс модальных групп, перемотка) — поведение контроллера после конца, в L1 не входит; исходный M-код — в source map. |

### 5.3 Фрейм (запись значений СК — операции над машинной таблицей)

| Оп | Поля | Источник / примечания |
|---|---|---|
| `wcs_define` | `p: 1..9, origin(vec3), state` | G10 L2 — **абсолютное** задание origin в машинных координатах. Семантика «запись в таблицу» сохраняется как узел; эквивалентность сравнивает узел покомпонентно. |
| `wcs_set_here` | `p: 1..9, delta(vec3), state` | G10 L20 — задание СК **относительно текущей позиции** → позиционно-зависим, как G92: разрешён только до первого motion-опа, иначе `E_UNSUPPORTED_SEMANTICS`. |
| — (поле `wcs`) | — | G54–G59.3 — **выбор**, не запись: поле состояния, не оп. |

**Правило невзаимозаменяемости:** `frame_preset` (G92), `wcs_set_here` (L20),
`wcs_define` (L2) — три разных узла с разной семантикой персистентности
(временный сдвиг / позиционно-относительная запись / абсолютная запись в
таблицу). Адаптер не подменяет одно другим без явного warning-кода.

**Правило machine-frame (v0.1):** опы с `frame = machine` (G53) выразимы
только если все машинные координаты статически известны, т.е.:
(a) в программе нет позиционно-относительных фреймовых операций
(`frame_preset`, `wcs_set_here`);
(b) каждая WCS, **выбранная в программе до соответствующего machine-frame
хода**, определена в ней же через `wcs_define` **до этого хода** (origin
известен из текста на момент хода; более позднее переопределение того же P
на более ранние ходы не влияет).
Иначе machine-frame ход — `E_RUNTIME_STATE`: `start` невыразим без знания
стартовой позиции станка / содержимого таблицы.
`wcs_define` разрешён в любой позиции программы (запись абсолютна,
позиционной независимости не нарушает); `frame_preset`/`wcs_set_here` —
только пресетка до первого motion-опа.

### 5.4 Сырое

| Оп | Поля | Примечания |
|---|---|---|
| `raw` | `payload (hex исходных байтов), reason, code, source_span` | §9. Same-dialect only; сериализация — grammar.ebnf D9 (v0.8: `text` → `payload`, один оп = одна строка). |

## 6. Каноническая форма дуги

```
arc := { start: vec3, end: vec3, center: vec3,
         direction: cw | ccw,
         sweep: (0°, 360°],          // явно, градусы
         pitch: float,               // винтовая компонента вдоль нормали плоскости, знаковая; 0 = плоская
         state }
```

Решения:

- **Явный `normal` (v0.1).** Векторное произведение `(start−center) ×
  (end−center)` вырождается при `sweep=360°` (start == end) → нормаль —
  **явное поле**, единичный вектор. Канонический знак: `normal` = +ось
  заявленной плоскости (G17 → +Z, G18 → +Y, G19 → +X); `direction`
  определён правилом правой руки относительно `normal`. Парсер выводит
  `normal` из выбора плоскости, канонизатор валидирует согласованность.
- **Явный `sweep`** устраняет обе ловушки: (а) start == end — нулевая дуга или
  полный круг? → в каноне `sweep=360°` (нулевой ход — не дуга, отбрасывается
  канонизатором с notice); (б) абсолютный vs инкрементальный центр
  (G90.1/G91.1 в LinuxCNC, только инкрементальный в GRBL) — канон поглощает
  различие, адаптеры эмитят в свой режим.
- **`pitch` обязателен** (может быть 0): винтовая интерполяция — обычный
  CAM-вывод (thread milling, helical ramping). Поддержка с первого дня.
- **R-форма** конвертируется при канонизации: знак R выбирает дугу ≤ 180° /
  > 180°; центр вычисляется из start, end, R, direction, normal.
- **Валидация узла (v0.1), допуски — `EQUIVALENCE.md`:**
  1. радиус — **планиметрический** (проекция на плоскость ⟂ `normal`):
     `ρ_start = |proj⊥(start−center)| ≈ ρ_end ≈ R` (3D-сравнение ломалось
     на винтовых дугах);
  2. нормальная компонента хорды: `(end−start)·normal ≈ pitch`;
  3. полное уравнение позиции (закрывает неоднозначность sweep vs 360°−sweep):
     `end ≈ center + Rot(normal, direction, sweep)·(start−center) + pitch·normal`.
  Невозможная дуга (планиметрическая хорда > 2R) — `E_INVALID_INPUT`,
  не unsupported.
- **R-форма — правила (v0.7):**
  1. R + винтовая компонента **валидна** (решение (ii) по ревью CORPUS
     v0.1): плоскость — модальное состояние парсера (§4) — даёт `normal`
     **до** вычисления центра; центр — из R в плоскости; `pitch` —
     вне-плоскостная компонента хода. Посылка «R не определяет плоскость
     винта» неверна: нормаль известна из G17/18/19. Приём R+off-axis
     диалектами-источниками — `?` COVERAGE §6.9 (сверка на этапе 3);
     семантика EID от этого не зависит.
  2. R при start == end — `E_INVALID_INPUT`: центр неоднозначен (знак R
     не разрешает); полный круг — только IJK-формой (оба контроллера
     ошибают R-полный-круг).

## 7. Canned cycles: правила развёртывания

EID **не хранит** G81/G8x как узлы. Разворачивание — при канонизации,
в явные `rapid`/`linear`/`arc`/`dwell`/`spindle`-изменения (изменения шпинделя
попадают в `state` последующих опов — resolved-state делает это возможным).

**Разворачиваемые** (пометка `?` = проверить по документации в COVERAGE-проходе):

| Цикл | Разворачивается в | Примечание |
|---|---|---|
| G81 (drill) | rapid→R, feed→Z_bottom, rapid→retract | |
| G82 (drill+dwell) | как G81 + `dwell` на дне | |
| G83 (peck, full retract) | цепочка с полным отводом на каждом пике | порядок пиков сохраняется |
| G73 (chip-break) | цепочка с отводом на Q над последней глубиной | LinuxCNC; в GRBL не существует, но разворачивается в универсальные ходы — проблем нет |
| G85 (bore, feed out) | feed in, feed out | |
| G86 (bore, spindle off, rapid out) | feed in, dwell P (если задан), `state(spindle=off)`, rapid out, `state(spindle=<прежнее направление и обороты>)` | LinuxCNC документирует рестарт: «restart the spindle in the direction it was going» (COVERAGE v0.0). Разворачивание **обязано** восстановить шпиндель, иначе меняется process intent |
| G89 (bore+dwell) | как G81 + dwell | |

**Отказ — `E_UNSUPPORTED_SEMANTICS`:**

| Конструкция | Причина |
|---|---|
| G84 / G74 (tapping) | синхронизация шпиндель-подача, реверс — не представимо ходами |
| G33 / G33.1 (spindle-synced) | то же |
| G76 (fine boring w/ shift) `?` | ориентация шпинделя M19 — проверить в COVERAGE |
| G87, G88 | LinuxCNC: «accepted, behavior undefined» (не реализованы); в Fanuc — ручное вмешательство / обратное сверление |

**Правила разворачивания (единые для всех циклов):**

1. **G98/G99 → явные ходы.** G98: отвод в initial Z (Z до начала цикла —
   вычислим статически, позиция определена предыдущими опами канонизатора).
   G99: отвод в R-плоскость.
2. **Повторы L/K** — разворачиваются; каждая итерация — полная последовательность
   ходов с абсолютными координатами (в GRBL K-повтор шагается инкрементально
   по X/Y — разрешается при разворачивании).
3. **Позиции — абсолютные.** Все инкрементальные режимы разрешены до
   построения опов.
4. **Порядок пиков сохраняется точно** (process intent: порядок = семантика
   для peck-циклов). Менять местами соседние пики запрещено.
5. Разворачивание детерминировано: два канонизатора на одном входе обязаны
   дать побитово одинаковый список опов.
6. **G98 требует определённой позиции (v0.1).** Initial Z вычислим только
   если позиция до начала цикла полностью определена предшествующими
   motion-опами. Цикл как первый motion-оп программы (или после
   позиционно-неопределённого участка) — `E_RUNTIME_STATE`: разворачивание
   было бы недетерминировано.

**Направление hobby→industrial даёт verbose-вывод** — документированное
поведение: GRBL→Fanuc эмиссия даст развёрнутую программу вместо G83.
Зафиксировано в §1.2 как не-цель («сворачивание запрещено»).

## 8. Не представимо в L1 — механизм, а не список

Всё, что парсер диалекта встретил и не может представить узлом L1, попадает
в **`raw`** с обязательными `reason` («почему») и `code` (диспозиция из
`COVERAGE.md`). Механизм покрывает:

- `E_UNSUPPORTED_SYNTAX` — грамматика диалекта шире L1 (вендорские макросы,
  коды вне словаря L1);
- `E_UNSUPPORTED_SEMANTICS` — синтаксис есть, семантика не представима ходами
  (G41/G42, G84, G38.x, M19, M60, M62–M68, M70–M73, …);
- `E_REQUIRES_MACHINE_TABLE` — значение зависит от машинной таблицы
  (G28/G30 home-позиции, G43 H — компенсация длины из таблицы; v0.0: отказ,
  узлы — решение этапа 8 с профилем);
- `E_RUNTIME_STATE` — §1.1 (`#`-параметры, system vars; поток управления —
  см. `E_UNSUPPORTED_SYNTAX`) + статически невыразимые позиции (block
  delete, M66, G98 первым motion-опом, machine-frame без известных
  origin — §5.3, ARC с `start=unknown` и частичный `end` на границах
  фреймов — §2);
- `E_INVALID_INPUT` — вход сломан (невозможная дуга, lexical-мусор):
  **не** unsupported, отдельный класс диагностики;
- `E_LIMIT_EXCEEDED` (v0.1) — **guard транслятора**, не свойство входа:
  max-число опов, max-итерации развёртывания, max-длина файла/слова.
  Пороги зафиксированы в `COVERAGE.md` §1.2; переопределение — профиль,
  этап 8. Поля диагностики: порог + фактическое значение.

**Единственное исключение из правила raw — `IGNORED_SAFE`:** лексические и
контрольные элементы без process-значения (N-слова, `%`, `G80` — отмена
cycle-моды, немодальной в L1). Класс узкий; расширение — только per-code в
`COVERAGE.md` с обоснованием и ревизией этого раздела (ревью §7.4).

**Правила RAW:**

1. RAW-оп выживает только в **same-dialect** round-trip (байт-в-байт).
2. Кросс-диалектная трансляция программы, содержащей RAW, — отказ целиком
   с `E_RAW_UNTRANSLATABLE` и перечнем блоков. Тишина недопустима:
   иначе этап 6 даст ложнозелёную эквивалентность на вендорских вставках.
3. Комментарии — **не RAW**: это аннотации (§11), несемантичны.
4. Смешанная программа (часть узлами, часть RAW) same-dialect — валидна,
   fidelity смешанная; каждая RAW-строка попадает в диагностику.

## 10. Числовая политика

1. **Хранение:** значения — в объявленных единицах программы (`units`),
   **verbatim** (десятичная строка + Decimal-зеркало). Конвертация единиц —
   только на границе эмиссии, когда единицы цели отличаются, с задокументированным
   округлением. Verbatim хранение делает same-dialect round-trip точным
   (без шума 1/25.4).
2. **Формат эмиссии EID-текста:** фиксированная десятичная запись, 4 знака,
   без экспоненты; трейлинг-нули нормализованы. (Формат пересматривается
   ревизией, не молча.)
3. **Сравнение** — numeric с масштабированным epsilon; формулы допусков —
   `EQUIVALENCE.md`, не здесь.
4. **Канал версии:** каждый golden-тест привязан к версии канонической формы
   (`eid_version` + версия этого документа). `eid_version` (magic-строка) =
   версия `grammar.ebnf`; изменение формата = новая eid_version +
   перегенерация golden с записью в CHANGELOG (v0.9 — иначе первое же
   изменение формата тихо ломает корпус).

## 11. Source maps и аннотации

- Каждый оп несёт `source_span: {file, line_start, line_end, cols}` в исходный
  диалектный файл. Обязательное поле.
- **Развёрнутые циклы (v0.1):** все производные опы несут тот же
  `source_span`, что и исходный блок цикла, плюс `sub_index: int` — позиция
  в развёрнутой последовательности. Без `sub_index` диагностика и Tier A
  неоднозначны.
- Комментарии исходника → аннотации опов (несемантичны): same-dialect round-trip
  сохраняет; кросс-диалектная эмиссия сохраняет, где диалект позволяет,
  без гарантии позиции; в эквивалентности не участвуют.

## 12. Текстовый формат EID

**Авторитетное определение — `grammar.ebnf` v0.1** (привязан к SPEC v0.8).
Этот раздел — ссылка и информативный пример, **не норма**: все правила
детерминизма живут в заголовке grammar.ebnf (D1–D10) — единственном
источнике, чтобы исключить дрейф двух описаний (v0.8, ревью). magic-строка
несёт **версию формата** (= версия grammar), не версию SPEC. golden AST
используют плейсхолдер `src=0.1-0.0` (диалект-независимость; EQUIVALENCE §3
исключает src из эквивалентности).

```
EID/L1 v0.1

- **один оп = одна физическая строка** (переносы — только для читаемости в
  этом документе, не в каноническом тексте);
- все числа — фиксированные 4 dp, без экспоненты, трейлинг-нули сохранены
  (§10.2);
- state-поля каждого не-RAW/не-PEND опа — **полный снапшот** (EQUIVALENCE §2),
  **фиксированный порядок**: feed, spindle, coolant, tool, frame, wcs;
- порядок осей в векторах и G92-блоке — X, Y, Z (EQUIVALENCE §1.4);
- `src=` — source span (§11) в форме `<line>.<col>-<line>.<col>`;
  производные опы развёрнутых циклов несут тот же `src` + `sub=<i>`;
- `PEND` — program_end-оп (§3: ровно один раз, последний; единственный —
  в минимальной программе). *(v0.7: прежний §12-пример не содержал
  program_end-оп — дрейф от инварианта §3, исправлен.)*

```
EID/L1 v0.7
UNITS mm
PATH_MODE exact_path
FRAME_PRESET G92 X0.0000 Y0.0000 Z5.0000 WCS G54
OP 001 RAPID start=0.0000,0.0000,5.0000 end=10.0000,0.0000,5.0000 src=12.1-12.44 feed=none spindle=off coolant=none tool=none frame=wcs wcs=G54
OP 002 WCS_SET_HERE p=2 delta=1.0000,0.0000,0.0000 src=13.1-13.42 feed=none spindle=off coolant=none tool=none frame=wcs wcs=G55
OP 003 LINEAR start=1.0000,0.0000,5.0000 end=1.0000,0.0000,0.0000 src=14.1-14.44 feed=120.0000 spindle=cw,12000.0000 coolant=flood tool=3 frame=wcs wcs=G55
OP 004 ARC start=1.0000,0.0000,0.0000 end=6.0000,5.0000,0.0000 center=6.0000,0.0000,0.0000 normal=0.0000,0.0000,1.0000 dir=cw sweep=90.0000 pitch=0.0000 src=15.1-15.44 feed=80.0000 spindle=cw,12000.0000 coolant=flood tool=3 frame=wcs wcs=G55
OP 005 DWELL seconds=0.5000 src=16.1-16.12 feed=80.0000 spindle=cw,12000.0000 coolant=flood tool=3 frame=wcs wcs=G55
OP 006 RAW reason="vendor macro" code=E_UNSUPPORTED_SYNTAX src=47.1-49.0
OP 007 PEND
END
```

## 13. Проверка ортогональности (вместо эвристики «>15 узлов»)

Инвентарь: **10 типов опов**. Критерий — не количество, а отсутствие полей,
зависящих от runtime. Чеклист по каждому полю:

| Поле | Runtime-зависимость | Вердикт |
|---|---|---|
| `feed` | модальное значение программы; разрешён в upm статически (G93, §4); G0 не сбрасывает | чисто |
| `normal` (дуга) | выводится парсером из заявленной плоскости, валидируется (§6) | чисто |
| `spindle`, `coolant`, `tool` | значения из текста программы | чисто |
| `sweep` | явный, не выводится из контекста | чисто |
| `frame_preset` | ограничен стартом программы (§3) | чисто под ограничением |
| `wcs_set_here` | ограничен стартом программы (§5.3) | чисто под ограничением |
| `state` в целом | нет «опциональных runtime-режимов» | чисто |

Если ревизия добавляет поле, смысл которого зависит от состояния станка в
момент исполнения — это L2 через чёрный ход. Отказ.

## 14. Открытые вопросы (нумерованные, каждый с дефолтом)

**Решено в v0.1:**

- **Q1** — G28/G30: отказ `E_REQUIRES_MACHINE_TABLE`; узел — решение этапа 8
  (профиль знает home-позиции). Для статического L1 это правильно.
- **Q3** — `path_mode` остаётся метаданными программы **после запрета
  серединных переключений** (§3): единственный режим на программу. Эмиссия в
  GRBL — warning с записью потери в source map: GRBL смешивает углы по своим
  настройкам, exact-stop терялся бы молча.
- **Q7** — 4 знака в inch подтверждены: 0.0001" ≈ 2.5 µm. Если первый
  inch-вектор Tier A потребует точнее — это ревизия numeric policy, не
  молчаливая правка.
- **Q8** — M1 = «равен отсутствию» в диффе; в `EQUIVALENCE.md` указать явно:
  исполнение M1 зависит от настройки станка, статическая эквивалентность его
  не гарантирует.
- **Q9** — снят документацией LinuxCNC (COVERAGE v0.0): G86 = feed на дно →
  dwell P сек → шпиндель off → rapid на clear Z → **рестарт шпинделя в
  прежнем направлении**. Разворачивание §7 восстанавливает
  `state(spindle)` после отвода.
