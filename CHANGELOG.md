(CORPUS §6: изменение формата = перегенерация/обновление golden + запись).

## SPEC-EID-L1

### v0.10 — 2026-11-20 (итерация 1: вопросы A2/A3 отчёта A — ревизии Q11)

Отчёт Агента A (32/32 теста) содержал 9 вопросов к документам. Решения
оркестратора:

1. **A2 → §2 (b), критерий РАЗНОСТИ:** start после смены wcs вычислим ⇔
   обе системы (исходная и целевая) имеют in-text origin —
   `reading_new = prev_end + O_prev − O_new`. Буквальная формулировка
   v0.8/v0.9 («новая система без define») была неточной: неопределённая
   исходная даёт тот же unknown.
2. **A3 → §2 (c)/(d), критерий вычислимости:** machine-frame start
   вычислим ⇔ нет `frame_preset` (Δ=0) И origin активной WCS определён
   in-text (L20-происхождение не считается). Безусловный «M₀ внешний»
   v0.9 был слишком консервативен — M₀ входит только через Δ.
   N1 (E_RUNTIME_STATE) не затронут — диспозиция канонизатора диалекта
   (решение A4 принято).
3. **A1 → grammar v0.2:** PATH_MODE blend принимает `t=` (G64 P-); magic
   = `EID/L1 v0.2`; все 7 golden обновлены (одна строка). Решение A4–A9
   принято как реализационное (диспозиции split, emitter валидирует,
   нумерация нормализуется, sweep=0 → drop, Notice-тип, предупреждение B).
4. §12: артефакт v0.7-правки устранён (маркированный список попал в
   code-fence с мусорной magic-строкой); пример = magic v0.2;
   OP 006 RAW дополнен обязательным `payload=` (grammar v0.2, замечание A).
5. Привязки EQUIVALENCE/CORPUS/PLAN обновлены (grammar v0.2, SPEC v0.10,
   COVERAGE v0.6).
6. **§8, правило 5 (правило двух классов):** структурные нарушения
   (искажают интерпретацию последующих опов) — жёсткий отказ; локальные
   конструкции — raw + диагностика. Разграничение — CORPUS §1.2 v0.5.
   Мотивация: противоречие COVERAGE `RAW(code)` ↔ ожиданиям отказов
   негативных векторов, обнаружено оркестратором перед итерацией 2.

### v0.1 — 2026-11-20 (точечная ревизия по ревью)

1. **§6 (дуга):** добавлено явное поле `normal`; валидация переведена на
   планиметрический радиус (проекция на плоскость ⟂ normal) + полное
   уравнение позиции. Причина: при `sweep=360°` start == end, векторное
   произведение нулевое — нормаль не выводилась; 3D-сравнение
   `|start−center|` ломалось на винтовых дугах.
2. **§4 (feed):** feed — модальное значение программы, G0 не сбрасывает;
   `none` только до первого F. Причина: в G-коде F переживает G0;
   «none на rapid» ломал resolved-state и расходился с поведением станка.
3. **§3/§5.3 (фреймы):** уточнена семантика `frame_preset` — координаты,
   присваиваемые текущей позиции, не «сдвиг»; введено правило machine-frame:
   G53 только при статически известных origin (нет позиционно-относительных
   пресеток; каждая выбранная WCS определена через `wcs_define`).
   Причина: позиционная независимость текла через G53 при неизвестном origin.
4. **§3 (path_mode):** глобален, серединные переключения G61/G64 — отказ.
   Причина: модальный код без поля состояния терялся молча.
5. **§3 (инвариант программы):** переформулирован — `program_end` ровно один
   раз и является последним опом. Причина: прежняя формулировка была
   противоречивой.
6. **§7 (правило 6):** G98 требует позиции, определённой предшествующими
   motion-опами; цикл как первый motion-оп — `E_RUNTIME_STATE`.
   Причина: initial Z при неизвестном старте делает разворачивание
   недетерминированным.
7. **§7 (G86):** рестарт шпинделя после отвода помечен `?` (Q9) до
   COVERAGE-прохода. Причина: разворачивание без рестарта меняет process
   intent, если диалект рестартует.
8. **§11:** `sub_index` для всех производных опов развёрнутых циклов.
   Причина: без него диагностика и Tier A неоднозначны на развёрнутых
   блоках.
9. **§14:** Q1, Q3, Q7, Q8 решены; добавлен Q9 (G86 restart).
